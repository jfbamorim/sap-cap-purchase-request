# sap-cap-purchase-request

> **Automotive Purchase Request Cockpit** — A full-stack procurement application built with SAP CAP, OData V4 and SAP Fiori Elements, simulating a realistic automotive manufacturing procurement scenario.

---

## Overview

This project implements an end-to-end **Purchase Request management system** for automotive manufacturing environments. It covers the full procurement lifecycle — from request creation and item management through multi-tier approval workflows — exposed via a centralised Fiori Elements cockpit.

Built as a learning and portfolio project demonstrating modern SAP development with **SAP Cloud Application Programming Model (CAP)**.

---

## Features

- 📋 **Purchase Request Management** — Create, edit, submit and cancel PRs with full lifecycle control
- 📦 **Item Management** — Multi-item PRs with material, supplier, quantity, price and delivery date
- ✅ **Approval Workflow** — Value-based approval thresholds with automatic and manual approval paths
- 📜 **Approval History** — Full audit trail of every approval action with actor, timestamp and value snapshot
- 🖥️ **Procurement Cockpit** — Centralised monitoring view with filters, KPI tiles and semantic visual indicators
- 🔴 **Business Rules Engine** — Validation layer enforcing procurement policies before every state transition

## Data Model

```
PurchaseRequest
├── items[]         → PurchaseRequestItem
│   ├── material    → Material
│   └── supplier    → Supplier
├── plant           → Plant
├── costCenter      → CostCenter
└── approvalLogs[]  → ApprovalLog
```

### PR Status Lifecycle

```
DRAFT ──► SUBMITTED ──► APPROVED
  │                └──► REJECTED ──► DRAFT (reopen)
  └──► CANCELLED
```

## Approval Thresholds

| Total Value | Approver |
|---|---|
| ≤ €1,000 | Automatic (SYSTEM) |
| €1,000 – €10,000 | Department Manager |
| €10,000 – €50,000 | Purchasing Manager |
| > €50,000 | Plant Manager |

## Getting Started

### Prerequisites

- Node.js 20 LTS
- SAP CDS CLI: `npm install -g @sap/cds-dk`
- VS Code with [SAP CDS Language Support](https://marketplace.visualstudio.com/items?itemName=SAPSE.vscode-cds)

### Installation

```bash
# Clone the repository
git clone https://github.com/jfbamorim/sap-cap-purchase-request.git
cd sap-cap-purchase-request

# Install dependencies
npm install

# Start the CAP server (with SQLite + seed data)
cds watch
```

The application will be available at `http://localhost:4004`.

### Seed Data

The project ships with realistic seed data covering all PR statuses and approval thresholds, ready for immediate demonstration. Data files are located in `db/data/`.

## OData Services

Once running, the following services are exposed:

| Service | Path | Description |
|---|---|---|
| `PRService` | `/odata/v4/pr` | Transactional service — CRUD + actions |
| `CockpitService` | `/odata/v4/cockpit` | Read-only cockpit aggregations |

### Available Actions

```
POST /odata/v4/pr/PurchaseRequests(key)/PRService.submitPR
POST /odata/v4/pr/PurchaseRequests(key)/PRService.approvePR
POST /odata/v4/pr/PurchaseRequests(key)/PRService.rejectPR
POST /odata/v4/pr/PurchaseRequests(key)/PRService.cancelPR
POST /odata/v4/pr/PurchaseRequests(key)/PRService.reopenPR
```

## Business Rules

Key validation rules enforced by the service layer:

- A PR must have **at least one item** before submission
- `requiredDate` must be **in the future**
- PRs with priority `HIGH` or `CRITICAL` require a **justification**
- Items with **critical materials** require a preferred supplier
- Approval actions are **role-restricted** based on PR total value
- Rejection requires a **reason** (minimum 10 characters)
